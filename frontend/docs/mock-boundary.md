# Mock Boundary

## 원칙

프론트만 설계하거나 구현할 때 mock 데이터는 코드와 별도로 작성한다.

## 허용

- `src/api` 뒤의 mock adapter
- 별도 fixture 파일
- 테스트/Storybook 전용 fixture
- API 계약을 표현하기 위한 정적 응답 샘플

## 금지

- 컴포넌트 내부 배열/객체로 업무 mock 데이터 작성
- 훅 내부에 임시 업무 데이터 삽입
- 백엔드가 제공하지 않은 비즈니스 값 생성
- API 실패를 빈 배열/성공 상태로 대체
- 모델 실패를 합격/불합격으로 변환
- 누락 필드를 UI 표시 편의용 기본값으로 채워 계약 불일치를 숨기는 처리

## 구현 기준

- mock은 실제 API 응답 형태와 동일한 interface를 사용한다.
- mock 데이터 파일은 화면 코드와 분리한다.
- mock이 계약 미확정 영역을 대신할 때는 문서에 "임시 데이터"가 아니라 "대체 구현체"로 기록한다.
- 백엔드 계약이 확정되면 mock도 같은 작업 단위에서 갱신한다.
