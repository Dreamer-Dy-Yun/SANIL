# Photo QA UI

## 화면 흐름

1. 로그인
2. 제품 선택
3. 검사 세션 시작
4. 기준 사진별 QA 대상 촬영
5. 전체 촬영 완료 후 처리 상태 확인
6. 최종 결과 확인
7. 검사 이력 조회

관리자 기준 사진 등록과 guide shape 관리는 작업자 기본 흐름이 아니라 `/admin/*` 관리자 영역에서 수행한다.

## 정보 구조

| 화면 | 사용자가 확인해야 하는 것 | 사용자가 할 수 있는 것 |
|---|---|---|
| 로그인 | 사용자 계정 상태 | 로그인 |
| 제품 선택 | 제품 드롭다운, 현재 선택값, 기준 사진 수, 바코드/QR 카메라 프레임 | 드롭다운 선택 또는 바코드/QR 촬영으로 제품 선택 후 검사 시작 |
| 기준 사진 목록 | 촬영 순서, 기준 이미지, guide shape 존재 여부 | 기준 사진 확인 |
| 관리자 기준 사진 관리 | 제품, 촬영 순서, 기준 이미지, guide shape 존재 여부 | 기준 사진 등록/수정 진입 |
| guide shape | 기준 이미지 위 가이드 | shape 확인/수정 |
| 검사 시작 | 제품, 총 촬영 단계 수 | 세션 생성 |
| 촬영 단계 | 현재 단계, 기준 이미지, overlay, 카메라 preview | 촬영, 재촬영, 확정 |
| 처리 대기 | 전체 처리 진행률, 실패 여부 | 새로고침, 결과 진입 |
| 결과 | 최종 상태, 개소별 근거, 이미지 비교 | 이력으로 이동, 재검사 시작 |

## 제품 선택 화면

제품 선택 화면의 하단 작업 버튼은 하나만 둔다. 제품이 선택되지 않은 상태에서는 `코드 촬영`으로 동작하고, 제품이 선택되면 같은 버튼이 `검사 시작`으로 바뀐다.

- 제품 선택은 제품 카드 목록이나 그리드가 아니라 단일 드롭다운 선택값으로 관리한다.
- 바코드/QR 촬영에 성공하면 제품 코드를 API 계약으로 조회하고, 조회된 제품을 같은 드롭다운 선택값에 반영한다.
- 바코드/QR 촬영 실패, 없는 제품 코드, 권한 문제는 선택값을 임의 보정하지 않고 오류 상태로 표시한다.
- 작업자 기본 화면에는 관리자 기준 사진 등록 폼을 배치하지 않는다.

## 관리자 기준 사진 관리 화면

- 기준 사진 등록은 일반 검사 작업 화면이 아니라 관리자 화면에서 수행한다.
- 제품별 복수 기준 사진을 등록할 수 있어야 한다.
- 기준 사진마다 `stepOrder`, 이름, 설명을 관리한다.
- 기준 사진 등록 후 guide shape를 확인하거나 편집할 수 있다.
- guide shape 좌표는 `origin: "top_left"`, `unit: "ratio"`만 사용한다.

## QA 대상 촬영 화면

- 한 화면에는 하나의 촬영 개소만 보여준다.
- 기준 사진 외곽선 또는 guide shape를 카메라 preview 위에 overlay한다.
- 촬영 지시는 촬영 이미지 영역 위에 표시하고, 촬영/확정 액션은 촬영 영역 하단에 둔다.
- 우측 기준 썸네일 패널, 좌측 고정 사이드바, 데스크톱형 보조 패널은 현장 촬영 화면에서 제외한다.
- 사용자가 모든 필수 촬영을 끝내기 전에는 최종 합부 결과를 보여주지 않는다.
- 개별 이미지의 백그라운드 처리 상태는 표시할 수 있지만, 개별 합부 결과는 최종 화면 전에는 숨긴다.
- 이미지 저장 또는 확정 실패 시 다음 단계로 이동하지 않는다.

## 결과 화면

- 최종 상태와 개소별 비교 근거를 함께 보여준다.
- 이미지 누락, 모델 실패, API 실패는 별도 실패 상태로 표시한다.
- `FAILED`는 처리 실패이지 합격/불합격이 아니다.
- 실패를 `PASSED` 또는 `REJECTED`로 변환하거나 빈 결과로 숨기지 않는다.

## Tablet UX 기준

- 대상 장비는 `M86XE` 계열 태블릿이다.
- 촬영 단계 화면은 portrait/landscape 양쪽에서 동작해야 한다.
- 주요 버튼은 충분한 터치 영역을 가져야 한다.
- 현장 조명에서 overlay가 보이도록 기준 이미지 투명도와 선 색상 대비를 조절할 수 있어야 한다.
- 카메라 권한 실패, 브라우저 미지원, 네트워크 실패는 각각 다른 상태로 표시한다.

## API 경계

- 화면은 API 또는 mock을 직접 호출하지 않는다.
- API 접근은 `src/api` 계층 뒤에 둔다.
- 백엔드 API가 확정되지 않은 값은 프론트에서 임의 생성하지 않는다.
