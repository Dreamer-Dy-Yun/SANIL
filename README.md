# SANIL

## 폴더 역할

| 경로 | 역할 | 갱신 기준 |
|---|---|---|
| `.github/` | GitHub Actions와 Pages 배포 자동화 | workflow, 배포 대상, 권한이 바뀔 때 |
| `AGENTS.md` | 저장소 전체 작업 원칙과 검증/커밋 기준 | 작업 원칙, 검증 기준, 하드닝 정의가 바뀔 때 |
| `docs/project/` | 산일전기 QA 프로젝트 배경, 범위, 기술 판단 | 고객 요구, 포함/제외 범위, 주요 의사결정이 바뀔 때 |
| `frontend/` | 프론트엔드 애플리케이션 경계 | 화면, API 호출 계층, mock 계약, 빌드 구조가 추가될 때 |
| `backend/` | 백엔드 애플리케이션과 API/DB 책임 경계 | API 계약, 라우터, 서비스, DB 접근, 인증/권한 구조가 추가될 때 |
| `backend/docs/database/` | 산일전기 DB 설계 문서 로컬 기준화 | 원본 DB 설계, 테이블, 관계, 미확정 이슈가 바뀔 때 |
| `mulAg/` | 멀티 에이전트 역할별 운영 문서 | 역할, 권한, plan/todo/review/done 흐름이 바뀔 때 |

## 현재 상태

- 현재 루트에는 `docs/`, `frontend/`, `backend/`, `mulAg/` 폴더가 있다.
- 1차 프로젝트 범위는 사진 기반 QA 합부 판정이며, 도면 기반 치수/공차 판정은 제외한다.
- `frontend/`는 React, Vite, TypeScript 기반 MVP와 mock API 구현을 가진다.
- `backend/`는 백엔드 소유 경계이며 아직 소스 파일이 없는 초기 상태다.
- Git 저장소는 이 루트를 기준으로 하며 GitHub Actions가 `frontend/`를 GitHub Pages로 배포한다.

## 경계 기준

- 화면, UI 상태, 브라우저 저장소, 프론트 전용 mock은 `frontend/` 책임이다.
- API 계약, 요청/응답 스키마, 인증/권한, 서비스 로직, DB 접근은 `backend/` 책임이다.
- 프론트와 백엔드의 계약이 바뀌면 양쪽 문서와 관련 타입/호출부를 함께 갱신한다.
- 한쪽 편의를 위해 다른 쪽 경계를 왜곡하지 않는다.
- 배포 자동화는 `.github/` 책임이며, 애플리케이션 빌드 산출물은 저장소에 커밋하지 않는다.

## 문서 갱신 규칙

- 새 폴더나 주요 파일이 추가되면 이 문서와 해당 폴더의 `README.md`를 함께 갱신한다.
- 기능, API 계약, 폴더 책임, 모듈 경계가 바뀌면 관련 문서를 같은 작업 단위에서 갱신한다.
- 경계가 불명확한 영역은 임의로 크게 고치지 말고 문제와 수정 방향을 먼저 문서에 기록한다.
