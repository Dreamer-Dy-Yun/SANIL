## 목적

SANIL 프론트의 기본 화면 성격을 데스크톱형 대시보드에서 M86XE 작업자용 태블릿 앱으로 재정의한다.

관리자 기준 사진 관리 화면은 예외적인 관리자 영역으로 분리하고, 작업자 기본 플로우인 제품 선택, 검사 촬영, 처리 대기, 결과, 이력은 큰 터치 영역과 최소 정보량을 갖는 현장 작업 UI로 새로 구성한다.

## 배경

사용자 검토에서 다음 의미가 확인되었다.

- 이 앱의 기본 사용자는 사무실 관리자가 아니라 QA 촬영 작업자다.
- 기준 사진 등록은 관리자 기능이므로 작업자 플로우에서 분리되어야 한다.
- 제품 선택은 드롭다운 또는 바코드/QR 카메라 촬영으로 선택값을 결정하는 단일 선택 흐름이어야 한다.
- 제품 카드 목록은 작업자 선택 흐름에 불필요하다.
- 촬영 화면은 우측 보조 패널이 아니라 촬영 영역 자체가 작업 단위여야 한다.
- 촬영 지시는 촬영 영역 상단, 촬영/확정 액션은 촬영 영역 하단에 있어야 한다.
- 작업자 화면에서 좌측 고정 사이드바와 데스크톱형 카드/패널 리듬은 장비 UX와 맞지 않는다.

## 범위

포함:

- 작업자 기본 shell 재작성
- 관리자 shell 또는 관리자 화면 성격 분리
- 제품 선택 화면 재구성
- 촬영/처리/결과/이력 화면 재구성
- 관련 스타일 재작성
- 관련 README와 설계 문서 갱신

제외:

- API 계약 변경
- mock fixture의 업무 데이터 변경
- 백엔드 구현
- DB 스키마 변경
- 실제 카메라/VLM 연동 구현

## 설계 기준

- 기본 앱은 작업자용 태블릿 UI다.
- 관리자 기능은 기본 작업자 플로우의 예외로 보고 별도 시각/레이아웃으로 분리한다.
- 작업자 화면은 1280 x 800 landscape 기준에서 스크롤 없이 주요 조작이 가능해야 한다.
- 촬영 중 네비게이션 노출은 최소화한다.
- 버튼은 최소 56px 이상의 터치 높이를 우선한다.
- 업무 mock 데이터는 page/component에 넣지 않고 기존 `src/api` 경계를 유지한다.
- 기존 API, camera adapter, scanner adapter 경계는 유지한다.
- 기존 데스크톱형 사이드바 중심 구조는 유지 대상이 아니다.

- 관련 문서가 새 레이아웃 계약과 일치해야 한다.

- 로컬 브라우저 검증에서 1280 x 800 또는 유사 viewport에서 제품 선택/촬영/결과 화면이 깨지지 않아야 한다.
