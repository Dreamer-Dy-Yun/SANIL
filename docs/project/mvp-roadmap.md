# MVP Roadmap

## MVP 목표

MVP는 산일전기 QA 담당자가 제품별 기준 사진을 등록하고, QA 대상 사진을 단계별로 촬영한 뒤, 최종 비교 결과를 확인할 수 있는 흐름을 검증한다.

## Phase 0: 설계 고정

목표:

- 제품 범위와 제외 범위를 문서화한다.
- 화면 흐름, API 계약, VLM 결과 계약을 고정한다.
- mock 경계와 fixture 위치를 정한다.

완료 기준:

- `docs/project/`
- `frontend/docs/`
- `backend/docs/database/`
- `mulAg/md/plan/active/`

위 문서들이 서로 같은 범위를 가리킨다.

## Phase 1: 프론트 Shell

목표:

- 웹앱 기본 라우팅과 화면 골격을 만든다.
- API adapter와 mock adapter를 먼저 만든다.
- 컴포넌트는 mock 데이터를 직접 알지 않는다.

화면:

- 로그인
- 제품 선택
- 기준 사진 목록
- 기준 사진 등록
- 검사 시작
- 단계형 촬영
- 결과 요약

## Phase 2: 촬영 UX

목표:

- 한 화면 한 촬영 단계 구조를 구현한다.
- 기준 사진 오버레이/외곽선 가이드를 제공한다.
- 촬영 확정 후 다음 단계로 이동한다.

완료 기준:

- 촬영자는 스크롤 없이 현재 촬영해야 할 항목 하나만 본다.
- 진행 단계와 남은 촬영 수가 명확하다.
- 촬영 누락 상태가 결과 화면으로 넘어가지 않는다.

## Phase 3: 판정 상태/결과 UX

목표:

- 개별 비교 처리 상태와 최종 집계 상태를 분리한다.
- 모든 촬영 완료 후에만 최종 결과를 표시한다.
- 실패/검토필요/불합격/합격을 명확히 구분한다.

완료 기준:

- 모델 실패가 합격/불합격으로 바뀌지 않는다.
- 검토 필요 항목이 최종 결과에서 별도로 드러난다.
- 촬영자/제품/기준 사진/QA 대상 사진 연결이 UI에서 추적 가능하다.

## Phase 4: 백엔드 구현

목표:

- PostgreSQL 스키마와 API를 구현한다.
- 이미지 저장소를 연결한다.
- VLM/LLM 작업 큐와 사용 로그를 구현한다.

선행 결정:

- `INSPECTION_SESSION.uuid` 생성 주체와 API `inspectionSessionUuid` 매핑
- 이미지 저장 root와 썸네일 정책
- LLM/API credential 저장 방식
- 권한 enum/check constraint

## Phase 5: 현장 PoC

목표:

- 실제 제품 1~2개로 기준 사진과 QA 대상 촬영 흐름을 검증한다.
- 촬영 가이드가 작업자 실수를 줄이는지 확인한다.
- VLM 결과가 어떤 유형의 결함에서 안정적인지 확인한다.

측정 지표:

- 촬영 누락률
- 재촬영률
- 모델 실패율
- `needs_review` 비율
- 사람이 최종 판정한 결과와 모델 보조 결과의 일치율
