# Project Scope

## 포함 범위

이번 프로젝트의 1차 범위는 사진 기반 QA 합부 판정이다.

1. 제품별 기준 대조군 사진을 등록한다.
2. 하나의 제품은 확인 개소, 사각지대, 촬영 각도 차이 때문에 복수 기준 사진을 가질 수 있다.
3. QA 대상 촬영 시 기준 사진 외곽선을 기반으로 촬영 가이드라인을 제공한다.
4. QA 대상 사진과 기준 사진을 VLM/LLM으로 비교한다.
5. 결과는 모든 촬영이 끝난 뒤 사용자에게 표시한다.
6. 촬영자, 제품, 기준 사진, QA 대상 사진, 판정 이력은 추적 가능해야 한다.

## 제외 범위

도면 기반 치수/공차 판정은 1차 범위에서 제외한다.

제외 사유:

- 일반 촬영 사진은 렌즈 왜곡, 원근, 촬영 거리, 제품 자세, 깊이 정보 부족의 영향을 받는다.
- 3D 스캐너, 비전 계측 장비, 고정 지그, 보정 표준 없이 공차 만족 여부를 보증하기 어렵다.
- 수출 QA 문제와 연결되는 업무이므로 보증 불가능한 결과를 시스템이 확정값처럼 제공하면 안 된다.

## 백엔드 범위

당분간 백엔드 구현은 보류할 수 있다.

다만 DB 설계 문서는 이미 제공된 원본 설계를 기준으로 유지하며, 향후 백엔드 구현 시 `PGDBManager`류 DB 접근 구조는 기존 이도 프로젝트의 패턴을 참고한다.

백엔드 구현 전에도 API 계약은 문서로 먼저 고정한다. 전체 촬영 결과를 묶는 검사 세션은 최신 DB 설계의 `INSPECTION_SESSION.uuid`를 `inspectionSessionUuid`로 노출하는 방향으로 잡는다.

## 프론트엔드 범위

프론트만 설계하거나 구현할 경우에도 mock은 코드와 분리한다.

- 화면/훅/컴포넌트 내부에 mock 데이터를 직접 넣지 않는다.
- mock은 API 계약을 표현하는 대체 구현체로만 둔다.
- 백엔드가 제공하지 않은 비즈니스 값을 프론트에서 생성하지 않는다.
- 폴백 데이터로 누락 계약을 숨기지 않는다.

## 대상 촬영 장비

고객사가 사용할 촬영 장비는 `M86XE` 계열 태블릿으로 본다.

정확한 OS, 브라우저, 카메라 사양은 아직 프로젝트 내부 기준으로 확정하지 않는다. 촬영 UI는 태블릿 현장 사용을 우선 고려하되, 실제 구현 전에는 [device-constraints.md](device-constraints.md)의 실기 확인 항목을 검증한다.
