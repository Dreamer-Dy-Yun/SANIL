# Backend

## 역할

`backend/`는 SANIL 백엔드 애플리케이션의 소유 경계다.

## 현재 상태

- 현재 이 폴더에는 소스 파일이 없다.
- 백엔드 프레임워크, 라우터, 서비스 계층, DB 접근 계층, 마이그레이션 방식은 아직 확정되지 않았다.
- DB 설계 기준 문서는 `docs/database/`에 정리되어 있다.

## 폴더 역할

| 경로 | 역할 | 갱신 기준 |
|---|---|---|
| `docs/` | 백엔드 계약과 설계 기준 문서 | API, DB, 인증/권한, 에러 형식이 바뀔 때 |
| `docs/database/` | 산일전기 DB 설계 문서 로컬 기준화 | 테이블, 필드, 관계, 미확정 이슈가 바뀔 때 |

## 향후 구조 기준

- API 계약, 요청/응답 스키마, 에러 형식을 명확히 유지한다.
- 라우터, 서비스/비즈니스 로직, DB 접근 책임을 섞지 않는다.
- 인증, 권한, 입력값 검증, 예외 처리, 트랜잭션 경계는 명시적으로 다룬다.
- 프론트 요구를 맞추기 위해 의미 없는 필드나 가짜 성공 상태를 만들지 않는다.
- mock/임시 구현은 실제 저장/수정/삭제가 된 것처럼 오해되지 않게 한다.
- 실패를 성공처럼 감추지 않는다.
- 불명확한 비즈니스 규칙은 임의로 확정하지 말고 계약 또는 TODO로 드러낸다.

## frontend와의 계약

- 프론트가 필요한 데이터는 API 계약으로 명확히 표현한다.
- 백엔드에서 제공하지 않는 비즈니스 값을 프론트가 임의 생성하지 않도록 계약을 먼저 정리한다.
- API 계약 변경 시 `frontend/`의 타입, 호출부, mock 계약 문서와 함께 갱신한다.

## 문서 갱신 기준

- 백엔드 소스 구조가 생성되면 이 문서에 폴더별 책임을 추가한다.
- API 계약, 인증/권한, DB 접근, 마이그레이션, 에러 형식이 바뀌면 관련 문서를 함께 갱신한다.
